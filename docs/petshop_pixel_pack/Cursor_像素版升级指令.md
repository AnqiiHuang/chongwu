# 宠物店像素版升级指令

版本：2026-10-20 / v2。面向现有项目 https://anqiihuang.github.io/chongwu/ 的增量升级。

使用方法：解压 `宠物店_像素素材与开发包.zip`，把其中 `petshop_pixel_pack` 整个文件夹放在项目根目录。将本文件交给 Cursor，输入：「请按这份升级指令直接修改当前项目，先检查现有代码，再分阶段完成全部本次验收项。」

以下正文就是给 Cursor 的完整任务。保留现有技术栈和有效经营功能；示例类型是字段责任示意，实际代码必须补全类型并适配现有项目。

## 1. 先检查当前项目，再增量修改

检查入口页面、创建流程、游戏状态、存档、角色数据、场景渲染和构建配置。先列出具体需要修改的文件，然后实施，不停留在分析或方案。

线上当前可见行为：进入即命名；六种装修是文字和色块；店址随机揭晓；店主采用整套头像并提供身高；三位员工固定入职。以下新需求替换这些行为。不得仅修改文案后宣称完成。

沿用每日 5 次行动、事件 3 个选项、第五次后 22:30 日报、等级/营业额/客流、库存、存档与既有故事。创建过程不推进游戏日期、不消耗行动点。不要删除进度来解决迁移问题，不要自动发布远端站点。

## 2. 新的完整进入流程

唯一顺序：资源准备 → 街景开场 → 标题菜单 → 宠物店命名 → 装修六选一 → 店址四选一 → 店主定制 → 店员三选二 → 正式营业。

状态建议：`BOOT / INTRO / TITLE / SHOP_NAME / INTERIOR / LOCATION / OWNER / STAFF / PLAYING`。使用显式状态与合法转移，避免用几个布尔变量互相覆盖。

创建页保留「上一步」，返回不会清空已填内容。各步骤草稿独立自动保存；刷新可继续创建。只有最终确认两名店员后，才一次性创建正式 GameState、初始化第 1 天和 5 次行动。连点确认不能建立两个存档或重复扣初始资金。

有有效正式存档时，标题页突出「继续经营」；另有「创建新的宠物店」「设置」。点击新建先提供导出旧档与确认替换，未确认前旧档仍可继续。已有创建草稿时显示「继续创建」。空存档的主按钮为「开始创建我的宠物店」。

## 3. 开场动画与真实加载

使用 `assets/scenes/opening_street.png`，这是一张横向街景，不是视频，也不是分层背景。通过镜头裁切窗口沿街平移、轻微推进，形成走近店铺的感觉。不要把整张图片旋转成倾斜街道，不要把单张图伪称为可自由旋转的 3D 场景。

建议首播约 7 秒，资产就绪后开始计时：

| 时间 | 画面 |
|---|---|
| 0～0.8 秒 | 街道从浅色遮罩中出现，先看到街道和树荫 |
| 0.8～4.5 秒 | 镜头从左向右移动，焦点逐渐转到画面右侧店铺 |
| 4.5～5.5 秒 | 缓慢推进、减速，停在招牌与橱窗前 |
| 5.5～6.2 秒 | 标题「震惊！我开了一家宠物店」出现 |
| 6.2～7 秒 | 副标题和创建/继续按钮依次出现，背景停稳 |

副标题：「从一声门铃开始，把小店变成温暖的家。」标题、招牌文字和按钮由 HTML 渲染，保证中文清晰。标题附近允许很轻的光照变化，不做频闪。

街景原图尺寸以 manifest 为准；店铺中心约在原图横向 72%、纵向 55%，实际手机构图需要预览调整。手机用固定竖屏视窗裁切宽图；桌面可适当扩大取景范围。店门、招牌和标题不能被按钮遮住。使用位移和缩放时限制边界，任何时刻不露空白。不要强行让整张 3:1 宽图缩进手机屏幕。

这张街景是通用标题背景，店址尚未选择；进入正式经营后，外景预览使用玩家选定的地址图片。

真实加载与演出分离：先加载开场图及首屏必要资源；加载进度来自已完成资源数量或已知字节，不用计时器假装下载。开场期间后台加载装修、店址、店主和店员图集，宠物/NPC 按需加载。不要让首次进入必须下载全部图集才看到内容。

右上保留「跳过开场」，跳过直接落到标题停帧，不能跳过必要资源校验。加载失败给重试入口；非关键资源失败不导致永久白屏。尊重减少动态效果设置，直接展示停帧。后续访问可直接显示标题，设置中可重播；音效等待首次用户交互后开启。

## 4. 宠物店命名

独立命名页，不提前堆经营面板。店名输入去除首尾空格，长度 2～12 个可见字符，支持中文；非法或过长时在字段附近提示，不静默截断。使用项目已有校验习惯，避免 emoji 被简单 UTF-16 长度误判。

提供招牌文字实时预览。确认后去装修页，店名写入草稿。默认示例「茸茸小屋」，不要替用户自动提交。

本包房间是完整背景图，没有可单独拆卸的柜台前景层。第一版人物站在清晰的地面区域，叠加装饰只放适配插槽。若需要人物走到柜台后方，必须额外做遮挡方案并验证，不能靠错误 z-index 蒙混过关。不要把背景里画好的家具当作已经可移动的家具。

天气、晨昏可叠轻微环境色，但不影响风格识别和文字对比。六套风格不设置初始价格差异，免费任选。

## 6. 店址由玩家四选一

删除随机抽址动作及「店址揭晓」流程。使用 `assets/scenes/locations_four.png`，每张卡都有独立图、名称、描述、优势和不足；点击大图预览，主动确认后才存档。

| locationId | 名称 | 描述 | 优势 | 不足 |
|---|---|---|---|---|
| residential | 中高端社区底商 | 社区门口，散步家庭来往稳定 | 预约服务较多；客单价初值 +10% | 租金初值 +15%；更重视服务细节 |
| old_town | 老城区步行街转角铺 | 有树荫与老邻居的小转角 | 租金 -10%；社区羁绊收益 +10% | 基础自然客流 -5% |
| university | 大学城周边商铺 | 校园附近，周末热闹 | 周末自然客流 +15%；实用商品好卖 | 平均客单价 -10%；预算敏感 |
| clinic | 宠物医院旁 | 安静护理与医院转介比较常见 | 护理类来客权重 +15% | 租金 +5%；普通零售客占比相应降低 |

这些数值是新一轮平衡起点，不是现实收益预测。医生转介通过正常剧情建立，选在医院旁不等于自动得到医疗资格。权重修正归一化，不能把来客比例加到超过 100%。避免把同一修正同时应用于客流、客单价和利润三次。四种地址都能完成全部主线，剧情不锁死在某地。

地址影响实际参数、社区描述和地址预览；不改变玩家已选的室内装修。六装修 × 四地址都是合法组合，共 24 种。

## 7. 店主定制：名字、独立穿搭、性格

删除身高选项及其必填逻辑；旧档 height 可保留为兼容字段，不再出现在 UI。默认 22 岁女性，名字可改，示例「祁见禾」。保留现有性格选择和解释；若当前为四种性格就沿用，不随意增加一整套新数值系统。

定制页上方始终显示完整店主，下方切换「发型 / 上衣 / 围裙 / 鞋子」四个分类。每类四件，全部免费，互不绑定。选择一件上衣时，发型、围裙和鞋子保持原选择。提供随机搭配和恢复默认，但必须只修改外观；名字和性格不会被重置。

| 类别 | 四件部件 |
|---|---|
| 发型 | 栗色短发、黑色低发髻、深棕卷发、蜜糖色披肩发 |
| 上衣 | 奶油衬衫、蜜桃短袖、蓝色条纹衬衫、芥末黄开衫 |
| 围裙 | 苔绿爪印、蜜桃小花、雾蓝小花、燕麦棕口袋 |
| 鞋子 | 棕色短靴、奶油运动鞋、棕色搭扣鞋、蓝灰帆布鞋 |

素材：`assets/customization/owner_base.png` 是正面基础人偶，`owner_wardrobe.png` 是 16 个部件图集。`assets/characters/owner_default.png` 是默认完整造型的三视和表情，不是可拆的衣服层。

需要真正实现正面纸娃娃合成。建议在统一逻辑画布上绘制基础身体、鞋、上衣、围裙和头发；脸部开口、手臂和衣领的覆盖关系逐项校准。为每个部件提供 `frameId / targetRect / zIndex / anchor`，把变换存在数据中，不在组件里堆位置补丁。两只鞋作为同一选择，可分别校准左右脚位置。

这些生成部件没有预先对齐到同一绑定骨架。必须制作开发模式定位工具：当前部件可调 x/y/宽高，显示基础身体对齐线，输出配置。最后关闭调试 UI。逐件检查露底、穿帮、围裙肩带、脸部遮挡及鞋底。不能把选中状态变了但预览没变视为完成。

用同一套穿搭状态合成定制页、营业页店主、玩家头像和档案头像。头像从合成结果的头肩区域显示，不能固定使用默认眼镜头像。默认完整立绘有圆框眼镜，而基础纸娃娃不含眼镜；本轮不额外增加眼镜分类，采用基础纸娃娃外观作为新建店主的最终显示。完整默认立绘作为角色设定及默认装束参考，不覆盖自定义结果。

4 × 4 × 4 × 4 = 256 种合法正面组合。当前素材只承诺默认造型三视与正面换装，不包含 256 套侧背造型或行走动画。经营场景第一版保持正面小立绘和轻微浮动；不要通过水平翻转假装背面。

## 9. 人物、宠物与剧情衔接

完整角色表见 `人物宠物设定.md`。图集帧见 `asset-manifest.json`，禁止凭文件序号猜人物名。核心人物和大黄各有 6 个表情，其余角色有日常、开心、担忧 3 个表情；所有角色都有正面、侧面、背面。

主线《这条街，多了一盏灯》保留八章：第一声门铃；窗边留一个位置；一张还没拍的全家福；大家都有一把钥匙；这盏灯为谁而亮；慢一点也没关系；不用一家店包办；大家都知道的那个地方。详见 `主线剧情_八章版.md`。

本轮先接上第一章的开店事件和主线数据接口；若项目已有后续故事，保留并修复角色引用。前四章 17 节点的完整脚本作为独立内容阶段实施，不用本轮新增大量文本阻塞创建流程升级。八章共 33 节点的大纲不等于 33 个已实现事件。

主线使用 `activeEmployees`、`primaryHelper` 等角色选择器。第一章整理价签和毛巾的旁白、第四章分工和合照、终章工作名单必须随真实雇员变化。未选林序时，照护记录可由店主承担；没有苏桃时，第四章冲突换成基础接待预约，不能强行出现高级美容；唐栗未入职时，合照细节由在场员工对应替换。某员工的个人成长只在他/她实际入职后发生。

现实、日常、温暖；没有超自然、复杂商战或角色强制死亡。动物保留自然毛色，宠物不同物种分区。主线不靠广告解锁；未达开放条件的节点可顺延，不到指定日就永久错过。

## 10. 数据与素材接入

建议字段，实际命名与现有项目保持一致：

```ts
type Appearance = {
  hairId: string;
  topId: string;
  apronId: string;
  shoesId: string;
};

type OnboardingDraft = {
  schemaVersion: number;
  step: 'SHOP_NAME' | 'INTERIOR' | 'LOCATION' | 'OWNER' | 'STAFF';
  shopName: string;
  styleId: string | null;
  locationId: string | null;
  ownerName: string;
  personalityId: string | null;
  appearance: Appearance;
  selectedEmployeeIds: string[];
};
```

正式存档中保存 styleId、locationId、appearance 和雇佣名单，开场播放偏好属于设置。开场播放结束不等于创建完成。不要只保存在 React 局部状态，刷新后又随机生成。

`asset-manifest.json` 含 16 张 PNG、各自宽高与 205 个显示区域。每个区域用原图像素坐标 `rect: {x,y,w,h}` 表示，不是 CSS 百分比。图集并非完全等宽等高，必须按各帧取图。需要缩放时保持各角色比例，不能把猫和成人都强制拉满同一个矩形。

把包内 `assets` 复制到项目实际静态资源目录，如 `public/assets/petshop/`；把 manifest 放入内容数据目录。注意 manifest 的 `imagePath` 是相对素材包根目录的路径，接入时统一映射，不重复拼接 `assets/assets`。

可采用 `<div>` 裁切背景图，或 Canvas `drawImage` 的源矩形参数取图。Canvas 显式设置 `imageSmoothingEnabled = false`；像素素材可设置 `image-rendering: pixelated`，正文保留正常字体渲染。图片与文字不可一起低分辨率缩放。避免过度放大、模糊滤镜、光滑矢量人物和 emoji 占位。

提供统一 AssetSprite/CharacterPortrait/ShopScene 组件，所有页面复用。配套帧矩形根据原图像素和透明区域整理；开发时仍要在正式显示尺寸检查耳朵、尾巴、发梢是否被裁切。`reviewRequired` 标记不可被忽略或在未验收时改成 false。

如果现项目是 Vite，所有动态资源地址走实际 `BASE_URL`，当前部署目录为 `/chongwu/`；不能在代码中写 `/assets/...` 导致 GitHub Pages 子目录部署 404。沿用现有兼容构建设置，不为本轮视觉升级重建工程或盲目更换依赖。

## 11. 移动端、美术和广告

统一清新、精致像素插画：暖棕边缘，奶油、浅绿、桃粉、小面积蓝色。人物约 2.5～3 头身，动物保持物种特点。界面可以用正常清晰中文字体配像素边框，不能因为像素风牺牲长文阅读。

以 390 px 手机宽为参考，覆盖 360～430 px；桌面为居中的游戏区域，开场可更宽。按钮触控高度至少 48 px；底部处理安全区与软键盘。创建页进度在命名之后出现：「店名 → 装修 → 店址 → 店主 → 伙伴」。任何一步不能横向溢出或用小字挤塞。

命名、装修、地址、捏脸、选员工、开场和标题页完全不插广告。正式经营保留原来的自选激励位置：日报正常结算后可额外领取 80 金币，布置页可领 3 片装饰布料。奖励不增加行动点；不看广告可正常通关。首三游戏日及首次前台 10 分钟不展示真实广告，沿用总频控。主线演出、领养交接、告别和终章收束不弹广告。

没有真实广告适配器时，生产版隐藏广告入口；开发环境的模拟必须清楚标注。不要加开屏强制广告，不要让广告成为加载完成或确认创建的必要步骤。

## 12. 旧存档迁移

先确认现有存档键、真实版本号、旧装修/地址/人物 id；制作实际映射，不臆造已经存在的字段。新 saveVersion 通过迁移函数补字段并备份旧值。

旧三员工存档继续保持原团队和经营进度。旧装修转换为对应图片场景；旧地址保留结果。旧整套店主头像映射为最接近的部件组合，并允许免费调整；不删旧姓名、性格、宠物、余额、进度或成就。无法识别的 id 使用明确的保底样式并记录说明，不能清空整份档案。

创建草稿和正式档分开存储；新建失败不覆盖旧正式档。外观设置改动不影响行动点或货币。处理 localStorage 不可用、无效数据、资源缺失和中途刷新，不能显示「保存成功」后实际丢失。

## 13. 分阶段实施与验收

顺序：A 素材注册与帧预览 → B 开场/标题/完整创建状态流 → C 六场景接入与真实换装 → D 店员选择、角色适配和迁移 → E 移动端验证与构建。全部完成后汇报，不能做完一个静态页面就结束。

必须实际验证：

1. 新存档按指定顺序走完；每步返回与刷新保留选择；新建不消耗行动。
2. 开场移动到店铺再停稳，标题和按钮出现；跳过、减少动态、资源失败均有正确结果。
3. 六种装修分别进入六个不同主场景；预览与正式经营对应。
4. 四个地址主动选择并持久化，参数只应用一次；任意装修可配任意地址。
5. 16 个换装部件逐件预览；切换一个分类不改变另外三个；头像、营业店主和存档外观一致。
6. 三种店员组合都可开局，每次恰好两人；工资正确；未入职人物不工作；主线不因缺某职业卡住。
7. 旧三人存档与已有宠物/余额/日期/剧情保持；旧玩家不被迫重新开店。
8. 实际完成五次行动，只有一次 22:30 日报；刷新不会重复结算。
9. 360、390、430 px 以及桌面检查，无裁切按钮、横向滚动、人物穿家具、图集邻帧漏出。
10. 项目已有构建命令通过；生产预览下 `/chongwu/` 资源可加载。未获发布指令时不自动上线。

为状态转移、迁移、员工约束和结算写必要测试。视觉布局以真实预览检查，不为每个色值写测试。最终列出改动文件、已实现行为、运行方式、实际验证结果和剩余素材/动作需求，不能把生成概念图说成已接入的行走动画。
